# DeepSeek Harness (`dsh`) — repo note (Tier-1: direct peer, same stack, ships what we listed as blocked)

Clone: `deepseek-ai/deepseek-harness` @ `b150a55`, 2026-08-21. MIT (harness) — but see **license** below, the Landlock helper is separately licensed BSD-3-Clause and separately published. TypeScript (~2,734 `.ts/.tsx` src files) across **55 workspace packages** + `apps/{cli,web}` + a `native/` dir. pnpm workspace, vitest, tsdown. **Verified structure** (cloned and read, not inferred).

This is the closest peer to ClutchCode found so far: same language, same package manager, same test runner, same problem (a model-agnostic agent harness), released by a frontier-model lab as a *developer preview* that says outright "THERE WILL BE COMPATIBILITY-BREAKING CHANGES." It matters less as a design validator than as a **source of two concrete unblockers** for rows we had marked blocked (§12.6 Landlock, §18.1 editor protocol) — see "reusable ideas."

## architecture
"Everything is a plugin," built on **Cordis** (a dependency-injection/plugin framework by the same ecosystem, with its own published paper on "spatiotemporal composability"). Services are registered on a context object (`ctx.llm`, `ctx.sessions`, `ctx.credentials`, `ctx.storage`, `ctx.subprocess`, …) and swapped by installing a different package. `docs/capability-seams.md` (machine-generated from the module graph) classifies every service as **core spine service**, **swappable capability seam**, or **bundle/composition point** — e.g. `ctx.sessionPersistence` is a seam with `session-persistence-jsonl` and `session-persistence-sqlite` implementations. Docs are auto-generated into mermaid graphs (`gen-doc-graphs.ts`) and fully bilingual (en/zh, plus `.i18n.yaml` sidecars).

## runtime model
Host/client split with an explicit `tsconfig.host.json` vs `tsconfig.base.client.json` boundary. `packages/host`, `packages/boot`, `packages/bundle` handle process/lifecycle; `apps/web` serves a local Web UI (`npx @deepseek-ai/dsh web`, default `127.0.0.1:3080`). Sessions are first-class and persisted, with a separate `session-query` (+ `session-query-sqlite`) read path — a CQRS-ish split we do not have.

## agent loop / tools / edit format
`packages/agent-loop`, `packages/tools`, `packages/plan`, `packages/goal`, `packages/todo`, `packages/workflow`, `packages/subagent`. Tool execution has its own documented pipeline (`docs/tool-execution-pipeline.md`) and catalog (`docs/tool-catalog.md`). Notably there is an `agent-loop-testkit` package — a first-class harness for testing the loop, analogous to our `FakeProvider`+replay. Edit format UNVERIFIED (not read this pass).

## model/provider abstraction *(high value)*
`ctx.llm` is a seam with `llm-deepseek`, `llm-pi-ai`, and — most interesting to us — **`llm-replay`**, plus a `token-meter` service documented as "Replay token measurement." That is the same bet as our recorded-transcript replay harness (§16.3c) and `FakeProvider`, independently arrived at, and it is registered as a swappable *provider* rather than a test fixture. Worth studying as a structural alternative to our approach.

## storage
`ctx.storage` "non-session storage hub" + `ctx.attachments` (durable binary attachment storage) + `ctx.sessionPersistence` (JSONL or SQLite) + a `spill` package. The JSONL/SQLite dual implementation behind one seam validates our own JSONL-events choice while leaving a SQLite path open (§19/ADR-007).

## config
`ctx.settings` seam with `settings-file`; documented `docs/config-catalog.md`. Also ships `hooks-claude-code` and `hooks-codex` packages — i.e. it deliberately consumes *other* harnesses' hook formats for compatibility, rather than defining only its own.

## CLI/TUI UX
`apps/cli` + `apps/web`. Web-UI-first for the documented entry point (`dsh web`), which is the opposite of our deliberate deprioritization of a web dashboard (§22). Not a signal to change course — different product bet, and ours is explicitly local-first-no-open-port (§17) — but worth recording that a peer chose the other branch.

## editor integration *(the highest-value section for us)*
`packages/acp/acp` is an **Agent Client Protocol** server, built on the official **`@agentclientprotocol/sdk` (0.25.1)**, spec at <https://agentclientprotocol.com>. Framed in their own docs as "an interoperability transport, not a presentation or human-interaction layer." A matching out-of-process **subagent client** lives at `subagent/subagent-acp`, so ACP is used bidirectionally (expose agents *and* consume them).

This is directly relevant because **`PROJECT_SPEC.md` already names ACP three times** (§18.1, §20's layer table, §26's risk register) and says our stdio JSON-RPC binding is "deliberately the **same shape as ACP** … so future editor clients are cheap," and that the mitigation for protocol-consolidation risk is "leaning into those protocols as a client rather than fighting them." We shaped `@clutchcode/agent-rpc` *like* ACP but never implemented ACP. There is now an official SDK and a working reference consumer.

## security/sandbox *(the other high-value section)*
`packages/sandbox/` is a chain of rungs behind one seam: `sandbox-local` (bwrap / Seatbelt / **Landlock**), `sandbox-windows-acl`, plus an `e2b` package for remote/cloud sandboxing. Real e2e tests exist per backend (`bwrap.e2e.ts`, `seatbelt.e2e.ts`, `landlock.e2e.ts`) — including the Seatbelt one we cannot run for lack of a macOS host. There is also a `guard` package and an `invariants` service ("package-owned invariant registry").

Three specifics matter to us:

1. **`native/landlock-run`** — a self-restrict-then-exec Landlock launcher, ~298 lines of C11 over the raw kernel UAPI, statically linked against musl, **fail-closed** ("if the kernel cannot enforce, it exits without running the command"). It installs a ruleset on *itself* then `exec`s the wrapped command, so the ruleset is inherited across `execve` and the *invoking* process stays unrestricted. Public API is deliberately tiny: `launcherPath()`, `grantArgs({readOnly, readWrite})`, and `probe() → 'full' | 'partial' | 'unusable'`.
2. **It is published on npm** as `@deepseek-ai/node-addon-landlock-run` (latest `0.1.1`, verified live against `registry.npmjs.org`), entry package + per-platform optional packages **`-linux-x64` and `-linux-arm64`**, with `os`/`cpu` fields so installers fetch only the matching one, and *no* install-time build fallback on purpose — on an unsupported host the path never resolves, `probe()` reports `unusable`, and the consumer falls closed.
3. **`docs/postmortem/0004-landlock-partial-notice-misclassified-child-failures.md`** — a real, resolved incident writeup. On older-ABI kernels the launcher prints exactly `landlock-run: partial enforcement (older Landlock ABI)` and *continues*; a launcher *failure* prints a different `landlock-run:` line and exits **125**. Their sandbox provider collapsed both into one case-insensitive substring `'landlock-run: '`, so any nonzero child exit carrying that prefix was blamed on the sandbox — ripgrep's exit-1-for-no-matches surfaced as `SANDBOX_UNAVAILABLE`. Their stated root cause is that the result type "could express only a bag of substrings" and could not say *failure requires exit 125*. Their own caveat is worth copying into our thinking verbatim in spirit: stderr is an in-band attribution channel, a confined child can deliberately forge the runner's fatal line, and "an out-of-band status protocol remains separate hardening, not a sandbox-bypass fix."

`sandbox-windows-acl` is a koffi-based port of a `WRITE_RESTRICTED`-token + restricting-SID mechanism (deterministic per-workspace SID, random per-session temp SID). It self-reports **`enforcement: 'partial'`**, not full, because ambient `Everyone` write ACEs and NTFS hard-links (ACLs belong to file objects, not paths) leak through. Their recorded design note rejects AppContainer because it "cannot do arbitrary-path reads at all," and rejects mxc for needing a Windows 11 24H2 floor.

## strengths
Genuinely modular seam architecture with machine-generated, bilingual, graph-backed docs; per-backend real e2e sandbox tests; published postmortems with root-cause analysis at a level most projects never write down; a shipped, fail-closed, prebuilt-for-arm64 Landlock launcher; bidirectional ACP; explicit interop with rival harnesses' hook formats.

## weaknesses (for our design)
Cordis DI is a large conceptual dependency and a contributor-onboarding cost — the same objection we recorded against opencode's Effect. 55 packages is a lot of surface for a preview-stage project that promises breaking changes. Web-UI-first conflicts with our local-first/no-open-port default (§17/§22). Their own sandbox honestly reports `partial` on Windows, so it is not an existence proof of *full* Windows confinement.

## reusable ideas
1. **Depend on `@deepseek-ai/node-addon-landlock-run`; do not write our own Landlock code.** This retires the exact objection in our own `HANDOFF.md` "What's left" row ("needs either a native helper binary or a vetted raw-syscall binding — neither exists yet, and a hand-rolled one carries a worse failure mode (silently over-permissive, not fail-loud)"). This helper is *fail-closed by design*, and consuming a published npm package is a **dependency decision, not a code-copy decision** — the same call we already made for `ajv` over hand-rolling JSON-Schema validation. Its `probe() → full|partial|unusable` maps cleanly onto our `detectSandboxBackend()`/`SandboxCapability` shape, and the `-linux-arm64` prebuilt means Landlock-on-arm64 does **not** inherit the blocker that stalls arm64 *seccomp* (no arm64 host to verify hand-derived syscall numbers against) — the helper carries that burden upstream.
2. **Implement ACP on top of `@clutchcode/agent-rpc`** via the official `@agentclientprotocol/sdk`. Open protocol ⇒ this is protocol conformance, the one verdict our own §2 already grants as genuine REUSE (same as MCP), not a clean-room problem. Delivers Zed/Neovim/Emacs clients for roughly the cost of one adapter, and executes the mitigation §26 already commits us to.
3. **Adopt postmortem 0004's classification lesson before we ever ship Landlock**: model runner failure as *status-gated* evidence (exit 125 **and** a fatal line, with exact informational lines excluded), never as a substring bag. This is a defect we would otherwise have shipped and rediscovered ourselves — our `classifyFailure` has already been bitten twice by exactly this shape of over-broad text matching (bare `"no such file or directory"`, and the `lint`/`typecheck` `ENV_ERROR_RE` gap).
4. **Model-free tool-result pruning as a distinct compaction stage** (`compaction-tool-result-pruner` behind a `ctx.toolResultPruner` seam, separate from `compaction-basic`). Our §4.5 budgeter currently compacts conversation history wholesale and folds the repo-map/file-window share into it; pruning *tool results* specifically is a cheaper, earlier lever we have not built.
5. **`llm-replay` as a registered provider rather than a test-only fake** — a structural alternative to `FakeProvider` worth considering if replay ever needs to be user-facing (§16.3c).

## explicitly do-not-copy
Do **not** adopt Cordis or the plugin/DI architecture — we deliberately chose direct package boundaries (§20), and retrofitting a DI container is a rewrite, not an improvement. Do not copy `sandbox-local`'s provider source, its Seatbelt profile strings, or its classification code: sandbox policy strings are **CLEAN-ROOM-REQUIRED + NEEDS-LEGAL-REVIEW if close** under `LICENSE_AND_REUSE_ANALYSIS.md §3`, and that applies here exactly as it does to Codex. Read postmortem 0004 for the *lesson* (status-gated classification) and write our own rules from our own `RunnerFailure` shape. Do not copy the Windows ACL port (it is itself a port of a third-party PoC, adding a provenance hop we do not want). Do not mirror the web-UI-first default (§17/§22). The `landlock-run` **binary is consumed as a dependency, never vendored** — no C source enters our tree.
